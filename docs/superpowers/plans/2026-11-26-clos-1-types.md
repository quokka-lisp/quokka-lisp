# CLOS sub-step 1 · Types — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Common Lisp's type system in the library — `type-of`, `typep`, `subtypep` as a real type algebra, `deftype`, `typecase`/`etypecase`/`ctypecase`, `check-type`, and `coerce` over any type specifier — so that ansi-test's `types-and-classes` group meets phase 2's bar.

**Architecture:** One new library file, `lisp/library/types.lisp`, loaded after `ratios.lisp`. `typep` evaluates a specifier directly against an object (fast, no algebra). `subtypep` parses both specifiers into canonical type objects in disjunctive normal form over disjoint *kinds* of object and asks whether `A ∧ ¬B` is empty, the approach of SBCL's `ctype` system. No Rust.

**Tech Stack:** Tier-1 Lisp (`lisp/library/`), differential tests against SBCL (`tests/lisp/*.lisp`, `tier1_cases!`), ansi-test runner (`crates/quokka-bootstrap/tests/ansi.rs`, `tests/ansi/`).

**Spec:** `docs/clos.md`, section *Types come first* and *Testing*; issue #124; phase tracker #123.

## Global Constraints

- Tier 1 is library code, compiled only; the interpreter never learns it. The new file goes in `boot::LIBRARY` (`crates/quokka-bootstrap/src/boot.rs`) and in `%library-files` (`lisp/library/rebuild.lisp`) in the same position — a test checks the two agree.
- `packages.lisp` stays the library's last file.
- The compiler never calls `typep`, `subtypep` or anything in `types.lisp`; the fixpoint (`the_compiler_reproduces_itself`, `a_rebuilt_world_is_the_same_world`) must stay green unchanged except for the rebuild's `(:FORMS … :REPLACED …)` counts.
- Every `%` name shares package `QUOKKA` with the compiler: `grep -rn "(defun %NAME\|(defmacro %NAME" lisp/` before adding one.
- A library file cannot use a `setf` place or macro defined in a later file.
- No float literal anywhere in the library (`%parse-double` on a string instead).
- Errors signal the condition type SBCL signals (a differential test prints `!! type-error` etc.).
- Behaviour matches SBCL (rule 6); where unsure, as SBCL does.
- `./scripts/check.sh` green before the one commit; no Claude attribution in the message.
- Lisp sources are embedded with `include_str!`: rebuild the `quokka` binary before `quokka build`.

## Review Focus

1. **A malformed specifier** — `(integer 5 a)`, `(member . x)`, `(and . 3)`, `(vector t 1 2)` — signals an `error` from `typep` and `subtypep`, never a fault or a hang.
2. **An unknown type name** — `(typep 1 'no-such-type)` signals an error as SBCL does; `(subtypep 'no-such-type 'integer)` returns `nil nil`, as SBCL does.
3. **A circular `deftype`** — `(deftype loop-a () 'loop-b) (deftype loop-b () 'loop-a)` — makes `typep` signal an error within the step budget, not exhaust the heap or panic.
4. **Mixed number kinds at range bounds** — `(typep (expt 2 70) '(integer 0 *))`, `(typep 1/2 '(real 0 (1)))`, `(typep 1 '(float 0 2))` (false: 1 is not a float), `(subtypep '(integer 1 5) '(real (0) 6))`.
5. **Deep or wide specifiers** — `(member …)` with 1,000 symbols, a `cons` type nested 20 deep — stay inside ansi-test's per-form step budget.

Each of these has its test in the task that owns the code.

`typep` dispatches on the expanded specifier: a symbol goes through a table of atomic type names → predicate (built once, an `eq` hash table); a structure name through `%find-layout` and `%structure-is-a`; a condition type name through `%condition-supertypes` against `%condition-type` (keep that lattice the only one); a list on its head (`and or not member eql satisfies cons integer rational ratio float short-float single-float double-float long-float real mod signed-byte unsigned-byte array simple-array vector simple-vector string simple-string base-string simple-base-string bit-vector simple-bit-vector complex function values`). `function` and `values` compound types signal an `error` (CLHS `typep`). All four float names are the one double format: `(typep 1.5 'single-float)` is true. `type-of` returns what SBCL's does for the cases above (`null`, `boolean`, `symbol`, `keyword`, `cons`, the structure's name, `double-float`, `hash-table`, `(integer 0 4611686018427387903)` for a non-negative fixnum, `fixnum` for a negative one, `bignum`, `ratio`, `(simple-array character (3))` for a string, `standard-char`/`base-char`/`character`).

### Task 2: Canonical types and `subtypep`

**Files:**
- Modify: `lisp/library/types.lisp` (or create `lisp/library/type-algebra.lisp`, listed after it — see File structure)
- Test: `tests/lisp/subtypep.lisp`, `.expected`; `subtypep => "subtypep"` in `tier1_cases!`

**Interfaces:**
- Consumes: `%expand-type` (Task 1).
- Produces: `(%parse-type specifier) → ctype`, `(%type-or a b)`, `(%type-and a b)`, `(%type-not a)`, `(%type-empty-p ctype) → (values empty-p certain-p)`, and `(subtypep type-1 type-2 &optional environment) → (values subtype-p certain-p)` = `%type-empty-p` of `(%type-and A (%type-not B))`.

The representation is the decision this task carries. A **ctype** is a list of components, at most one per **kind**, the kinds disjoint and together covering every object:

| kind | restriction carried | notes |
| --- | --- | --- |
| `:integer` | sorted disjoint closed intervals, bounds integer or `*` | `(integer (0) 5)` becomes `[1,5]` |
| `:ratio` | intervals over rationals with open/closed bounds | `rational`/`real` ranges contribute to both `:integer` and `:ratio` |
| `:float` | intervals with open/closed bounds | all four float names; `-0.0` treated as `0.0` |
| `:character` | sorted disjoint code ranges | `base-char` = codes below 128, `standard-char` = its 96 codes, as SBCL |
| `:symbol` | `(:in syms)` or `(:not-in syms)` | non-keyword symbols; `nil` and `t` are members |
| `:keyword` | `(:in syms)` or `(:not-in syms)` | |
| `:cons` | union of `(car-ctype . cdr-ctype)` | negation of a cons type is the union of `(¬car . t)` and `(t . ¬cdr)` |
| `:array` | union of `(element simple-p dims)` | element is the *upgraded* type (`t`, `character`, `bit`, `nil`); `simple-p` is `t`, `nil` or `*`; dims `*` or a list of `*`/integers |
| `:structure` | set of layouts, closed under `:include` | a structure name means every layout that includes it, computed from the layouts that exist when asked |
| `:condition` | set of condition type names | from `%condition-supertypes` |
| `:function`, `:hash-table`, `:package`, `:readtable`, `:random-state`, `:other` | all or nothing | `stream`s are structures today |
| `:unknown` | list of `satisfies` (and unparseable) specifiers | forces `certain-p` nil unless the answer is decided without them |

`(%type-not a)` complements each kind's restriction and adds every kind `a` lacks. Emptiness: every component's restriction is empty; a `:cons` component is empty when car or cdr is empty; `:unknown` makes the answer uncertain unless another component is non-empty. `t` is every kind unrestricted, `nil` the empty list. Class names join in sub-step 2 as one more kind.
